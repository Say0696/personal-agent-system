# Computer Development Profile

Use this as a neutral software-project workflow. Read the user's local computer-development profile for personal conventions before execution.

- Before editing, inspect the project entrypoints, relevant instructions, Git status, and current processes or ports when runtime state matters.
- Preserve existing uncommitted changes. Prefer reversible edits and bounded commands.
- Build before browser or endpoint testing. A successful build does not prove that a server, route, desktop window, or interaction is usable.
- Distinguish current command output from source inspection, old logs, and hypotheses. Confirm a suspected cause with a controlled check before stating it as fact.
- After changes, run the smallest meaningful build/test/smoke check and report the exact result.

Keep personal tool, shell, framework, and reporting preferences in local memory, never in this public skill.
